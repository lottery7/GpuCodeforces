# Автоматические замеры

Пакет оптимизации содержит исходное решение на каждом процессоре задачи (`starter.cu` или
`starter.<процессор><расширение>`), пакет угадывания - `first<расширение>` и `second<расширение>`
на единственном процессоре задачи.
Автор не задает время: поля `baselineTimeMs`, `firstTimeMs` и `secondTimeMs` в `format.json`
отклоняются, включая значения `null`.

Backend создает отдельное задание judge для каждого исходного кода и процессора (`ReferenceJob.processor`,
`language`), только на процессорах, которые предлагает платформа. Используется полный `ProblemSpec`
с генератором и всеми тестами, тот же процессор и та же агрегация, что у пользовательских решений;
результат — score процессора (`score`, `scoreType`). Код должен пройти проверку корректности и лимиты. Задания эталонов
не создают пользовательские посылки, не влияют на таблицу соревнования и рейтинг.

## Актуальность

Замер привязан к неизменяемой версии задачи и отпечатку среды своего процессора. Версия включает тесты,
генератор, код и метрику. Отпечаток среды `gpu-cuda` учитывает режим исполнения, имя GPU,
фактическую модель живого оборудования, состояние фиксации частот, версию исполнителя и компиляторов.
Отпечаток эмулятора — процессор, режим исполнения и признак тестового исполнителя: версии эмуляторов
зафиксированы в образах судьи. Пока ни один живой исполнитель не обслуживает процессор, замер ждет.

Backend получает список исполнителей через `GET /api/v1/executors` gateway. Неоднородное
или недоступное оборудование не позволяет использовать прежние времена как актуальные.
Смена модели GPU под прежним именем также запускает новые задания. Результат judge
проверяется по фактическому оборудованию и режиму; запоздалое событие старого задания не
делает новое поколение готовым. Несколько одинаковых GPU могут обслуживать один процессор.
Их компиляторы должны совпадать; исполнитель без сведений о компиляторе не используется
для актуальных замеров. При обновлении этой версии обновите также judge-executor.

Обновление пакета запускает замеры новой версии. Контест сохраняет закрепленную версию тестов;
для нее замер выполняется отдельно. Рекорды пользовательских решений сравниваются только
в текущей среде. Старые и тестовые результаты сохраняются в истории, но не участвуют в новом улучшении.

## Состояния

- `pending`: ожидается оборудование или отправка задания.
- `running`: исполнитель проверяет и измеряет код.
- `ready`: все необходимые коды прошли проверку, результаты доступны.
- `failed`: подготовка не удалась; публичный ответ содержит короткое описание без скрытых данных.

В `Problem.processors[].referenceMeasurement` для каждого процессора возвращаются состояние, ключ поколения
и время завершения. Результат исходного решения (`baselineScore`) доступен только после `ready`.
В угадывании оба результата остаются закрыты
до ответа, а `POST /guess` до готовности возвращает 503. Страница обновляет состояние автоматически.

Задания и их прогресс хранятся в PostgreSQL. Повторная отправка использует тот же идентификатор;
инфраструктурные сбои допускают ограниченные повторы. Перезапуск backend не теряет очередь.
События обрабатываются с учетом идентификатора задания, поколения и порядка событий.
Подробности ошибки и исходные результаты тестов остаются в БД и серверных логах.

Перед отправкой пользовательской посылки и эталона сохраняется снимок ожидаемой среды.
Результат сопоставляется с ним по процессору, модели, компиляторам, исполнителю, GPU,
версии исполнителя и фиксации частот. Поэтому запоздалый результат среды A остается в A,
даже если платформа уже перешла на B. Результат из B не получает отпечаток A.
Эталоны чужой среды повторяются с ограниченным числом попыток. Предыдущий лучший результат
пользователя пересчитывается для фактической среды и только по более ранним посылкам.
Старые исполнители без новых полей подтверждаются только текущим монитором;
их результат не приписывается прежней среде по одному сохраненному отпечатку.

## История ответов

При ответе сохраняется снимок обоих результатов с типом score, объяснения, поколения и признака тестового
результата. История не пересчитывает правильность по текущему окружению. Одна попытка разрешена на пользователя,
версию задачи, контекст и поколение измерений. Времена старых ответов сохраняются при миграции.
