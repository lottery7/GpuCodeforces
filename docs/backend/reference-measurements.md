# Автоматические замеры

Пакет оптимизации содержит исходный `starter.cu`, пакет угадывания - `first.cu` и `second.cu`.
Автор не задает время: поля `baselineTimeMs`, `firstTimeMs` и `secondTimeMs` в `format.json`
отклоняются, включая значения `null`.

Backend создает отдельное задание judge для каждого исходного кода. Используется полный
`ProblemSpec` с генератором и всеми тестами, тот же профиль GPU и та же агрегация, что у
пользовательских решений. Код должен пройти проверку корректности и лимиты. Задания эталонов
не создают пользовательские посылки, не влияют на таблицу соревнования и рейтинг.

## Актуальность

Замер привязан к неизменяемой версии задачи и отпечатку среды. Версия включает тесты,
генератор, код и метрику. Отпечаток среды учитывает режим исполнения, настроенный профиль
и имя GPU, фактическую модель живого оборудования, состояние фиксации частот,
версию исполнителя и компиляторов.

Backend получает список исполнителей через `GET /api/v1/executors` gateway. Неоднородное
или недоступное оборудование не позволяет использовать прежние времена как актуальные.
Смена модели GPU под прежним именем профиля также запускает новые задания. Результат judge
проверяется по фактическому оборудованию и режиму; запоздалое событие старого задания не
делает новое поколение готовым. Несколько одинаковых GPU могут обслуживать один профиль.
Их компиляторы должны совпадать; исполнитель без сведений о компиляторе не используется
для актуальных замеров. При обновлении этой версии обновите также judge-executor.

Обновление пакета запускает замеры новой версии. Контест сохраняет закрепленную версию тестов;
для нее замер выполняется отдельно. Рекорды пользовательских решений сравниваются только
в текущей среде. Старые и тестовые времена сохраняются в истории, но не участвуют в новом ускорении.

## Состояния

- `pending`: ожидается оборудование или отправка задания.
- `running`: исполнитель проверяет и измеряет код.
- `ready`: все необходимые коды прошли проверку, времена доступны.
- `failed`: подготовка не удалась; публичный ответ содержит короткое описание без скрытых данных.

В `Problem.referenceMeasurement` возвращаются состояние, ключ поколения и время завершения.
Время исходного решения доступно только после `ready`. В угадывании оба времени остаются закрыты
до ответа, а `POST /guess` до готовности возвращает 503. Страница обновляет состояние автоматически.

Задания и их прогресс хранятся в PostgreSQL. Повторная отправка использует тот же идентификатор;
инфраструктурные сбои допускают ограниченные повторы. Перезапуск backend не теряет очередь.
События обрабатываются с учетом идентификатора задания, поколения и порядка событий.
Подробности ошибки и исходные результаты тестов остаются в БД и серверных логах.

## История ответов

При ответе сохраняется снимок обоих времен, объяснения, поколения и признака тестового результата.
История не пересчитывает правильность по текущей GPU. Одна попытка разрешена на пользователя,
версию задачи, контекст и поколение измерений. Времена старых ответов сохраняются при миграции.
