# Форматы

Платформа поддерживает обычные задачи, оптимизацию данного решения и угадывание более быстрого кода.
Формат выбирается в пакете задачи, фильтр находится в банке. Все три формата доступны в контестах.
В дуэли участвуют обычные задачи и оптимизация с отправкой кода. Старые пакеты и контесты сохраняют обычный формат.

## Дуэль

Кнопка "Создать дуэль" открывает `/duels/new`. Настройки: случайный соперник или конкретный ник,
а также список тем. Пустой список означает любые темы. Достаточно совпадения хотя бы одной
выбранной темы; при подборе двух пользователей задача должна подходить обоим.

Случайный поиск сопоставляет двух ожидающих пользователей. При выборе ника соперник получает
приглашение в уведомлениях и может принять или отклонить его. Входящее приглашение не мешает
собственному поиску. При принятии собственный поиск или исходящее приглашение отменяется.

Задача выбирается случайно из опубликованных задач с отправкой кода. До подбора или принятия
приглашения она не раскрывается. Дуэль начинается сразу и длится 30 минут. Оба участника
регистрируются автоматически. Дата, название и задача через форму контеста не задаются.

Поиск можно отменить; он истекает через 15 минут. Приглашение действует 24 часа. Состояние
хранится на сервере и восстанавливается после перезагрузки. Принятие и подбор атомарны:
повторный запрос не создает вторую дуэль. Один пользователь участвует в одной активной дуэли.

В комнате видны таймер и результаты обоих участников. После конца побеждает участник с первым
местом в таблице; равные результаты означают ничью. Дуэли используют общий рейтинг соревнований.
API и хранение: [duels.md](duels.md).

Место определяется числом решенных задач, затем суммарным временем сдачи от начала соревнования
до первой принятой посылки каждой задачи. Правильное угадывание дает одну решенную задачу; время
его отправки учитывается в таблице. Время GPU показывается отдельно и не влияет на место.

## Оптимизация

Добавьте в пакет рабочее исходное решение `starter.cu` и `format.json`:

```json
{
  "format":"optimization",
  "baselineTimeMs":2.5,
  "benchmark":{
    "inputDescription":"Один и тот же набор размеров входа для обоих решений",
    "aggregation":"geometric_mean"
  }
}
```

`baselineTimeMs` - положительное время исходного решения на GPU платформы, измеренное на тех же тестах
и по той же методике. Значение задает автор пакета; backend не запускает исходное решение для его проверки.
При смене GPU или тестов обновите эталонное время вместе с пакетом.

Редактор открывается с исходным кодом. Вкладка "Исходное решение" доступна для чтения, вкладка
"Ваше решение" сохраняет правки и историю отмены. Решение проходит проверку корректности и замер.
Ускорение относительно исходного решения равно
`baselineTimeMs / bestTimeMs`. Корректное решение принимается и тогда, когда оно медленнее исходного.
В контесте место зависит от времени первой принятой посылки. Ускорение показывается отдельно.

## Угадай, какой код быстрее

Добавьте в пакет `first.cu`, `second.cu` и `format.json`:

```json
{
  "format":"guess",
  "firstTimeMs":1.2,
  "secondTimeMs":2.4,
  "explanation":"Первый вариант читает соседние элементы соседними потоками.",
  "benchmark":{
    "inputDescription":"Одинаковый набор входов и одинаковое оборудование",
    "aggregation":"geometric_mean"
  }
}
```

Оба варианта должны решать одну задачу. Времена положительные, измерены на одинаковых входах,
GPU и по одной методике. Равные значения означают ответ "Одинаково". `problem.json`, `problem.py`
и `statement.md` сохраняют обычный формат пакета и описывают условия сравнения.

## Метрика сравнения

`benchmark.inputDescription` описывает конкретный набор данных. `aggregation` задает итоговую метрику:

- `geometric_mean`: геометрическое среднее времен всех тестов, `exp(sum(log(t)) / n)`. Отношение
  двух таких результатов равно геометрическому среднему относительных ускорений по тестам.
- `max`: время самого медленного теста. Оно отражает худший случай набора.

Обычные задачи и старые пакеты без `benchmark` сохраняют `max`. Метрики не смешиваются в рекордах:
определение benchmark входит в конфигурацию проверки задачи. Исходное время и времена вариантов
должны использовать ту же агрегацию. Время решения сохраняется только после прохождения всех тестов.

Способ замера берется из `ProblemSpec`: `wall` учитывает вызов `solve` до завершения работы GPU,
включая запуск и синхронизацию; `gpu_kernels` учитывает объединение интервалов работы ядер.
Прогрев выполняется на первом тесте. Повторные замеры с медианой выполняются только рядом с лимитом,
а не на каждом тесте. Изменение агрегации не меняет этот протокол исполнителя.

Backend сохраняет фактические времена тестов, число запусков, оборудование и признак тестового
исполнителя в снимке посылки. Публичный API возвращает только сводку без исходных тестов и отладки.
Некорректный или неполный замер получает `measurement_error` и допускает повторную проверку.

В интерфейсе показаны входные данные, метрика и целевая GPU. В режиме `JUDGE_MODE=mock` модель GPU
не показывается; одно сообщение на странице объясняет, что код не исполняется и результаты тестовые.

## Ответ на угадывание

До ответа API возвращает только два кода. Пользователь выбирает первый, второй или одинаковое время.
`POST /api/problems/{id}/guess?context=practice` принимает `{"choice":"first"}`;
другие значения - `second` и `equal`. Для контеста передайте его ID в `context`.

Нужен вход. В контесте также нужны регистрация и текущая фаза live. На пользователя, версию задачи
и контекст сохраняется один ответ. Повтор того же запроса возвращает сохраненную попытку; другой
выбор отклоняется. Перезагрузка страницы восстанавливает результат. Изменение пакета создает новую версию.

Ответ сохраняется в истории посылок со статусом `accepted` или `wrong_answer`. GPU не запускается,
`timeMs` остается `null`; такой ответ не участвует в рекордах времени GPU. Только автору
попытки API возвращает `guessResult`: выбор, правильный выбор, оба времени и объяснение. В списках
посылок и чужой детали этого поля нет. Обычная отправка CUDA и проверка примера для guess запрещены.

### Сравнение своих посылок

API позволяет создать сравнение из двух своих принятых решений с объяснением.
Создание сравнения публикует оба кода как новую задачу guess в общем банке.
API: `POST /api/problems/{id}/comparisons` с `firstSubmissionId`, `secondSubmissionId` и `explanation`.

Backend проверяет автора, положительные времена, одну конфигурацию проверки и GPU платформы.
Исторические версии допустимы, если условия и метрики обоих замеров совпадают. Черновые задачи, угадывания,
чужие посылки и решения незавершенного контеста использовать нельзя. Объяснение обязательно, до
4000 символов. Сравнение сохраняется отдельно от импортируемых пакетов, обновление репозитория его
не удаляет. Замеры и объяснение доступны решающему после ответа.

API скрывает ответ до попытки, но пользователи с доступом к исходному репозиторию пакетов могут прочитать
`format.json`. Для соревнований, где ответ должен оставаться закрытым, ограничьте доступ к репозиторию.
