# Форматы

Платформа поддерживает обычные задачи, оптимизацию данного решения и угадывание более быстрого кода.
Формат выбирается в пакете задачи, фильтр находится в банке. Все три формата доступны в контестах.
Форматы работают на любом процессоре платформы (`gpu-cuda`, `rtl`, `riscv-rvv`, `cuda-sim`): результат
везде — score процессора (время, такты, такты × глубина × транзисторы, взвешенные инструкции), меньше — лучше.
В дуэли участвуют обычные задачи и оптимизация с отправкой кода. Старые пакеты и контесты сохраняют обычный формат.

## Дуэль

Кнопка "Создать дуэль" открывает `/duels/new`. Настройки: случайный соперник или конкретный ник,
а также список тем. Пустой список означает любые темы. Достаточно совпадения хотя бы одной
выбранной темы; при подборе двух пользователей задача должна подходить обоим.

Случайный поиск сопоставляет двух ожидающих пользователей. При выборе ника соперник получает
приглашение в уведомлениях и может принять или отклонить его. Входящее приглашение не мешает
собственному поиску. При принятии собственный поиск или исходящее приглашение отменяется.

Дуэль проводится на одном процессоре, он выбирается при создании; темы и задача берутся из задач,
которые можно сдавать на нем. Случайный поиск сводит только ждущих дуэль на том же процессоре.

Задача выбирается случайно из опубликованных задач с отправкой кода. До подбора или принятия
приглашения она не раскрывается. Дуэль начинается сразу и длится 30 минут. Оба участника
регистрируются автоматически. Дата, название и задача через форму контеста не задаются.

Поиск можно отменить; он истекает через 15 минут. Приглашение действует 24 часа. Состояние
хранится на сервере и восстанавливается после перезагрузки. Принятие и подбор атомарны:
повторный запрос не создает вторую дуэль. Один пользователь участвует в одной активной дуэли.

В комнате видны таймер и результаты обоих участников. После конца побеждает участник с первым
местом в таблице; равные результаты означают ничью. Дуэли используют общий рейтинг соревнований.
API и хранение: [duels.md](duels.md).

Место определяется числом решенных задач, затем суммарным временем сдачи от начала соревнования
до первой принятой посылки каждой задачи. Правильное угадывание дает одну решенную задачу; время
его отправки учитывается в таблице. Score показывается отдельно и не влияет на место.

## Оптимизация

Добавьте в пакет рабочее исходное решение на каждом процессоре задачи — шаблон его первого языка
(`starter.<процессор><расширение>`, для CUDA также `starter.cu`) — и `format.json`:

```json
{
  "format":"optimization",
  "benchmark":{
    "inputDescription":"Один и тот же набор размеров входа для обоих решений",
    "aggregation":"geometric_mean"
  }
}
```

Backend отправляет исходное решение каждого процессора исполнителю этого процессора на полный набор тестов.
После корректного выполнения API возвращает вычисленный `processors[].baselineScore`. Поля времени
в `format.json` запрещены. При изменении кода, тестов, метрики или окружения процессора (для `gpu-cuda` — GPU)
платформа автоматически запускает новый замер. До его завершения редактор доступен, исходный результат
и улучшение не показываются. Процессор, который платформа не предлагает, не измеряется.

Редактор открывается с исходным кодом. Вкладка "Исходное решение" доступна для чтения, вкладка
"Ваше решение" сохраняет правки и историю отмены. Решение проходит проверку корректности и замер.
Улучшение относительно исходного решения на процессоре равно
`baselineScore / bestScore` (на `gpu-cuda` это ускорение по времени). Корректное решение принимается
и тогда, когда оно хуже исходного. В контесте место зависит от времени первой принятой посылки.
Улучшение показывается отдельно.

## Угадай, какой код быстрее

Угадывание сравнивает два кода на одном процессоре и одном языке: в `problem.json` ровно один процессор
с одним языком (без `processors` — `gpu-cuda` и CUDA). Добавьте в пакет `first<расширение>`,
`second<расширение>` (`first.cu`, `first.sv`, `first.c`, …) и `format.json`:

```json
{
  "format":"guess",
  "explanation":"Первый вариант читает соседние элементы соседними потоками.",
  "benchmark":{
    "inputDescription":"Одинаковый набор входов и одинаковое оборудование",
    "aggregation":"geometric_mean"
  }
}
```

Оба варианта должны решать одну задачу. Платформа проверяет и измеряет каждый вариант на полном
наборе тестов, в одном окружении процессора и по одной методике. До завершения обоих замеров ответить нельзя.
Если код не проходит проверку, задача показывает ошибку подготовки без раскрытия ответа.
Равные итоговые значения означают ответ "Одинаково". `problem.json`, `problem.py`
и `statement.md` сохраняют обычный формат пакета и описывают условия сравнения.
Объяснение описывает отличия кода; правильный вариант платформа определяет по текущим замерам,
и он может измениться после смены окружения (например, GPU).

## Метрика сравнения

`benchmark.inputDescription` описывает конкретный набор данных. `aggregation` задает итоговую метрику:

- `geometric_mean`: геометрическое среднее времен всех тестов, `exp(sum(log(t)) / n)`. Отношение
  двух таких результатов равно геометрическому среднему относительных ускорений по тестам.
- `max`: время самого медленного теста. Оно отражает худший случай набора.

Обычные задачи и старые пакеты без `benchmark` сохраняют `max`. Метрики не смешиваются в рекордах:
определение benchmark входит в конфигурацию проверки задачи. Исходный код и оба варианта проходят
тот же исполнитель и агрегацию. Время решения сохраняется только после прохождения всех тестов.

Способ замера времени на `gpu-cuda` берется из `ProblemSpec`: `wall` учитывает вызов `solve` до завершения работы GPU,
включая запуск и синхронизацию; `gpu_kernels` учитывает объединение интервалов работы ядер.
Прогрев выполняется на первом тесте. Повторные замеры с медианой выполняются только рядом с лимитом,
а не на каждом тесте. Эмуляторы считают score детерминированно. Изменение агрегации
не меняет протокол исполнителя.

Backend сохраняет фактические времена тестов, число запусков, оборудование и признак тестового
исполнителя в снимке посылки. Публичный API возвращает только сводку без исходных тестов и отладки.
Некорректный или неполный замер получает `measurement_error` и допускает повторную проверку.

В интерфейсе показаны входные данные, метрика и модель процессора. В режиме `JUDGE_MODE=mock` модель
не показывается; одно сообщение на странице объясняет, что код не исполняется и результаты тестовые.

## Ответ на угадывание

До ответа API возвращает только два кода. Пользователь выбирает первый, второй или одинаковый результат.
`POST /api/problems/{id}/guess?context=practice` принимает `choice` (`first`, `second` или `equal`)
и обязательный `benchmarkKey` из текущего `processors[0].referenceMeasurement.key`. Устаревший ключ отклоняется
без сохранения попытки. Для контеста передайте его ID в `context`.

Нужен вход. В контесте также нужны регистрация и текущая фаза live. На пользователя, версию задачи
и контекст сохраняется один ответ на поколение замеров. Повтор того же запроса возвращает
сохраненную попытку; другой выбор отклоняется. После смены окружения процессора доступна новая попытка.
Изменение пакета создает новую версию. Предыдущие ответы хранят собственные результаты и объяснение,
поэтому пересчет не меняет их результат задним числом.

Ответ сохраняется в истории посылок со статусом `accepted` или `wrong_answer` на процессоре задачи. В момент
ответа ничего не запускается, `score` остается `null`; такой ответ не участвует в рекордах. Только автору
попытки API возвращает `guessResult`: выбор, правильный выбор, `firstScore`, `secondScore` и объяснение. В списках
посылок и чужой детали этого поля нет. Обычная отправка кода и проверка примера для guess запрещены.

### Сравнение своих посылок

API позволяет создать сравнение из двух своих принятых решений с объяснением.
Создание сравнения публикует оба кода как новую задачу guess в общем банке.
API: `POST /api/problems/{id}/comparisons` с `firstSubmissionId`, `secondSubmissionId` и `explanation`.

Backend проверяет автора, положительные score, один процессор и язык обеих посылок, одну конфигурацию
проверки и окружение процессора платформы. Новая задача guess получает этот процессор и язык.
Исторические версии допустимы, если условия и метрики обоих замеров совпадают. Черновые задачи, угадывания,
чужие посылки и решения незавершенного контеста использовать нельзя. Объяснение обязательно, до
4000 символов. Сравнение сохраняется отдельно от импортируемых пакетов, обновление репозитория его
не удаляет. Оба кода заново проверяются и измеряются платформой. Замеры и объяснение доступны
решающему после ответа.

Хранение заданий, актуальность оборудования и восстановление после сбоя:
[reference-measurements.md](reference-measurements.md).

API скрывает ответ до попытки, но пользователи с доступом к исходному репозиторию пакетов могут прочитать
объяснение из `format.json`. Для соревнований, где ответ должен оставаться закрытым,
ограничьте доступ к репозиторию.
