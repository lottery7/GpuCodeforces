# Поиск дуэли и уведомления

`POST /api/duels` принимает `mode: random|invite`, `topics`, `processor` и для приглашения `opponentHandle`.
Сервер возвращает `DuelRequest`; в нем нет задачи до начала дуэли. Доступные темы:
`GET /api/duels/topics?processor=…` (без параметра - по всем процессорам платформы).

Состояния: `queued`, `invited`, `matched`, `declined`, `cancelled`, `expired`.
`GET /api/duels/current` восстанавливает собственный активный запрос или начавшуюся дуэль;
при отсутствии возвращает 204. `GET /api/duels/{id}` доступен только участникам запроса.
`POST /api/duels/{id}/accept`, `/decline`, `/cancel` принимают и отменяют запросы.

При случайном поиске выбирается первый совместимый ожидающий пользователь на том же процессоре
и случайная задача этого процессора, подходящая фильтрам обоих. При принятии приглашения выбирается задача по его темам. В обоих
случаях создается обычная запись `Contest` с форматом `duel` на процессоре запроса, закрепленной версией задачи,
началом в момент подбора и двумя регистрациями. Старый путь создания дуэли через `/api/contests`
закрыт; редактирование дуэлей через форму контеста тоже закрыто.

Операции подбора и смены состояния выполняются в транзакции под общей блокировкой PostgreSQL.
Активный слот пользователя связан с исходящим запросом, затем с текущей дуэлью. Входящие
приглашения слот не занимают. Истекшие запросы и слоты завершенных дуэлей освобождаются при
обращении к сервису и периодической очистке. Два одновременных запроса не создают две комнаты.

`GET /api/notifications?offset=0&limit=20` возвращает свои уведомления, общее число и число
непрочитанных. `PUT /api/notifications/{id}/read` отмечает свое уведомление прочитанным.
Чужие уведомления недоступны. Типы: `duel_invitation`, `duel_started`, `duel_declined`, `duel_cancelled`.
В ответ включен текущий `duelStatus`, поэтому у отмененного или истекшего приглашения нет действий
принятия. Старые уведомления доступны через пагинацию. Письма и сообщения во внешние сервисы не уходят.
