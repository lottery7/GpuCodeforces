# Frontend

React, TypeScript, Vite. Дизайн основан на макетах из `docs/frontend/mockups`.
Нужен Node 24 и pnpm, версия закреплена в `package.json`.

## Запуск

```sh
cd frontend
corepack enable
pnpm install --frozen-lockfile
pnpm dev
```

Открыть `http://127.0.0.1:5173`. Запросы `/api` проксируются на
`http://127.0.0.1:8080`. Другой backend:

```sh
API_PROXY_TARGET=http://127.0.0.1:8081 pnpm dev
```

Полный стек с backend и тестовым исполнителем запускается из корня:

```sh
JUDGE_MODE=mock docker compose --profile app --profile mock up -d --wait --build
```

Frontend доступен на `http://localhost:3000`. В этом режиме нужна регистрация;
демо-аккаунты ниже существуют только в тестовом HTTP-сервере.
Для проверки интерфейса без полного стека в двух терминалах:

```sh
pnpm api:demo
```

```sh
pnpm dev:demo
```

Тестовый HTTP-сервер слушает `127.0.0.1:4187`, хранит данные в памяти и
сбрасывает их при перезапуске. Аккаунты: `alex_cuda`, `new_cuda`, `author_cuda`.
Пароль: `password123`. `new_cuda` начинает без рейтинга, посылок и участия.
Тестовый сервер не входит в сборку приложения.

## API и состояние

`pnpm generate:api` создает типы из `../docs/frontend/openapi.yaml`.
Генерация также выполняется перед запуском, тестами и сборкой.
`src/api/client.ts` вызывает все операции через `openapi-fetch`.
Сгенерированные типы не хранятся в Git, несовместимость с контрактом ломает сборку.

TanStack Query хранит серверные данные, повторяет чтение при временной ошибке
и обновляет текущие результаты. Запросы отменяются при смене страницы,
опрос посылки прекращается после вердикта, в фоновой вкладке опрос приостановлен.
Изменяющие запросы автоматически не повторяются.

Сессия использует HttpOnly cookie и `credentials: include`.
Frontend и `/api` должны быть на одном origin. Backend проверяет Origin
и выставляет cookie согласно контракту. Пароли и токены не сохраняются в браузере.
При смене пользователя кеш серверных данных очищается.
Черновики кода сохраняются локально отдельно для пользователя, задачи, контеста,
процессора и языка; черновики, сохранённые до процессоров, читаются как CUDA для `gpu-cuda`.

## Процессоры

Каталог процессоров (`GET /api/processors`) загружается один раз за сессию (`src/processors.ts`).
На странице задачи выбираются процессор и язык (в контесте процессор задан контестом): от этой пары
зависят шаблон, лимит, блок "Среда и замер", лидеры, подсветка редактора и имя скачиваемого файла.
Результат посылки - score с типом; `ScoreValue` показывает число с единицей (`мс`, `такты`,
`такты * глубина * транзисторы`, `усл. такты`), надпись "Время GPU" - только у `gpu-cuda`. Список задач и контестов
фильтруется по процессору, рейтинг и профиль показывают отдельный рейтинг каждого процессора,
в редакторе контеста выбирается процессор и в пул попадают только задачи, которые на нём сдаются.

Фильтры, контекст задачи, процессор и пагинация находятся в URL. Архив контеста открывает
его условие и конфигурацию, переход к практике выполняется явно.
Пакеты задач подготавливаются вне платформы. Варианты для сравнения можно создать из своих принятых посылок.
Подготовка пакетов, частные задачи и восстановление пароля в MVP не входят.

В банке есть форматы "Решение с нуля", "Оптимизация решения" и "Угадай, какой код быстрее".
Формат выбирается фильтром и сохраняется в URL. В оптимизации редактор содержит исходный код
выбранного процессора, рядом показаны его исходный результат, личный результат и улучшение
(отношение score, у `gpu-cuda` - ускорение по времени). Вкладка исходного кода доступна
для чтения; переключение не сбрасывает правки и историю отмены.

Исходное решение (на каждом процессоре задачи) и оба варианта угадывания (на единственном процессоре
задачи) платформа измеряет автоматически; состояние замера показано у выбранного процессора.
Страница формата обновляет замеры каждые 5 секунд, в том числе после готовности, чтобы заметить
смену среды или версии задачи. Обновление не сбрасывает черновик редактора.
В оптимизации можно редактировать и отправлять код сразу; исходный результат и улучшение появятся
после готовности измерения. При ошибке показана короткая причина без старых результатов.
В угадывании отправка ответа доступна только после готовности обоих измерений.
Смена окружения меняет ключ эталона и открывает новую попытку; выбранный вариант и разбор
старых условий на странице задачи сбрасываются. Старые ответы в истории сохраняют свои результаты
и пометку тестового запуска.
Вместе с выбором отправляется ключ измерения. Если условия успели измениться, сервер отклоняет
запрос без сохранения попытки, а страница загружает новые условия.

В угадывании показаны два готовых кода. Ответить можно один раз на поколение замеров версии задачи в каждом контексте.
После ответа открываются результаты выбранного процессора и объяснение. Ответ сохраняется в истории;
правильный ответ засчитывается как решенная задача без собственной метрики запуска.
Таблица обычного контеста учитывает число решенных задач и время от начала до первой принятой посылки,
включая ответы на угадывание. Время GPU на место не влияет.
Выбранный ответ и разбор в посылке доступны ее автору.

Выбор угадывания находится прямо под вариантами кода; "Одинаково" - отдельная карточка.
После ответа на том же экране показаны правильный вариант, результаты и объяснение.
Метрика видна в строке "Замеры"; описание входов и методика раскрываются по нажатию.
В оптимизации показатели находятся над редактором, без повторного заголовка и инструкций.
Единицы результата переносятся под числом; на узком экране карточки перестраиваются в две колонки.
В коде только для чтения нет повторяющейся служебной строки редактора.

Раздел `/duels` содержит активные комнаты, приглашения и историю. Создание новой дуэли не закрывает
уже идущие. В `/duels/new` доступны "Случайный соперник" и "Выбрать соперника" с подсказками ников.
Для конкретного соперника отдельно выбирается случайная задача или "Выбрать задачу".
В форме выбирается процессор; поиск задач учитывает его, название, номер и идентификатор,
с фильтром сложности и пагинацией. Смена процессора сбрасывает выбранную задачу.
Выбранная задача сохраняется при изменении поиска и показывается компактной карточкой.
Выбора тем нет. Поиск и приглашение можно отменить.
При сбое каталога процессоров доступен повтор загрузки; пустой каталог блокирует отправку.
Поздний ответ на создание, отмену или принятие не возвращает пользователя со страницы, на которую он уже перешел.
Комната открывается после подбора или принятия, сам список не перенаправляет в одну из комнат.

Колокольчик в шапке не содержит видимого текста; доступное название, подсказка и счетчик сохранены.
Панель уведомлений показывает приглашения, начало дуэли, отказ, отмену и сдачу. Приглашение можно принять
или отклонить прямо в панели. Уведомления и счетчик непрочитанных хранятся на сервере,
обновление каждые 5 секунд. Панель работает на мобильном экране и закрывается по Escape.
Список дуэлей фильтруется по процессору. Случайный поиск подбирает соперника на том же процессоре;
для смены процессора нужно отменить прежний поиск. Уже начатые комнаты продолжают работать.
Комната и страница задачи используют одну доску с таймером, местами и лучшим score кода.
Побеждает наименьший score принятого кода за 1/2/3 часа по сложности задачи. Более ранняя отправка
не дает преимущества. Кнопка сдачи с подтверждением завершает дуэль поражением; другие комнаты
продолжаются. При сдаче победитель может не иметь принятого решения. Равные результаты дают ничью.
После таймера доска дожидается проверок своевременных посылок и загружает финальную таблицу.
При сбое итогового запроса опрос продолжается, доступна кнопка повтора.
Локальный тестовый режим обозначен одним сообщением на странице; код в нем не выполняется.
В списке и заголовке посылки показан короткий ID, полный остается в ссылке.
Переход к задаче сохраняет процессор и язык. Из принятой посылки соревнования можно перейти к его результатам.

## Обратная связь

На широком экране условие и редактор занимают оставшуюся высоту окна.
Длинное условие и код прокручиваются отдельно. Результат примера, ошибки
и отмена загрузки находятся у кнопок редактора; длинный журнал имеет свою прокрутку.
На узком или низком экране страница прокручивается обычным образом,
а кнопки с результатом остаются в пределах редактора.
Крестик в углу вывода закрывает сообщение и возвращает фокус к условию, сохраняя код и черновик.
Ctrl+Z отменяет правку, Ctrl+Shift+Z возвращает ее; на macOS также работают Cmd+Z и Cmd+Shift+Z.

Ошибки сохранения и регистрации показываются рядом с соответствующим действием.
Если новая ошибка после действия оказалась за краем экрана, видимой становится
ближайшая область сообщения. Фоновые обновления не перемещают страницу
и не удаляют введенные данные формы. На странице посылки вердикт остается виден
при чтении исходника, повтор проверки расположен перед журналом ошибок.

## Проверка и сборка

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm preview
```

CI устанавливает зависимости по lock-файлу, запускает сценарные тесты
и собирает приложение с типами из актуального OpenAPI.
Проверяются сессии, черновики, статусы посылок и сценарии контестов.
Также CI собирает Docker-образ и проверяет прямые ссылки на страницы,
загрузку ресурсов, ответ 404 для отсутствующих скриптов и проксирование API.
`dist` содержит готовую статику. Сервер должен возвращать `index.html` для
маршрутов приложения и проксировать `/api` на backend с сохранением Host и Origin.
В production нужен HTTPS.

Из корня репозитория можно собрать контейнер:

```sh
docker build -f frontend/Dockerfile -t gpu-forces-frontend .
```

Конфигурация `nginx.conf` ожидает backend по адресу `backend:8080` в сети
контейнеров. При другом размещении замените upstream.
В production контейнер доступен через TLS-терминатор во внутренней сети.
Терминатор должен сохранять Host и перезаписывать X-Forwarded-Proto,
backend - учитывать заголовки только от доверенного прокси.
